# 백엔드 흐름도 기준 프런트엔드 정리

기준 자료: `PUF_데이터흐름_정리_v3.pdf` (2026-10-16). 이 문서는 화면/API 요구를 정리한 흐름도이며, 구체적인 URL·HTTP 메서드·요청/응답 JSON은 확정하지 않습니다. 서버 계약은 팀 백엔드 담당자와 맞춰야 합니다.

## 프런트엔드에서 유지할 범위

대부분의 기존 화면은 흐름도의 MP(관리자 웹), CP(고객 웹), CA(고객 앱) 기능에 대응합니다. 화면마다 백엔드 API가 아직 없다는 이유만으로 화면을 지울 필요는 없습니다. 흐름도에 없는 MP11(별도 배수펌프 위험도 화면)은 MP20 예지보전으로 합쳐졌고, MP17 타이머 알림은 제거된 상태라 별도 화면을 추가하지 않습니다.

고객 지도는 `/c-map`을 대표 경로로 사용합니다. `/c-map-preview`와 `/c-live-map`은 이 화면 내부에서 모드에 따라 선택하는 구현용 화면이므로 직접 진입 경로는 `/c-map`으로 돌립니다. 두 Vue 컴포넌트는 지도 화면의 미리보기/실데이터 구현에 계속 쓰입니다.

## 백엔드에서 우선 제공해야 할 기능

| 흐름도 기능 | 현재 프런트 경로 | 필요한 서버 책임 |
|---|---|---|
| 관리자 로그인·가입·승인 MP01~03 | `/shift-login` | 관리자 계정, 전화 인증, `PENDING` 승인 및 `ACTIVE`/`WITHDRAWN` 상태 처리, 담당 지역 범위 적용 |
| 관리자 지도·현황 MP04~09 | `/admin-dashboard`, `/fac-list`, `/fac-detail` | 지하차도·위험도·예측·CCTV·날씨 조회와 지역별 집계 |
| 수동 통제·전광판 MP10, MP10-1, MP10-2 | `/fac-detail`, `/fac-new`, `/pm-settings` | 담당 지역 내 수동 통제, 전광판 문구/프리셋, 변경 이력 및 이벤트 저장. 자동 제어로 처리하지 않음 |
| 문의·공지 MP13~15 및 교대 배정 | `/cs-customers`, `/cs-inquiries`, `/cs-content`, `/notifications`, `/shift-login` | 문의 답변, 공지·FAQ·첨부 관리, 공지 알림과 채널별 발송 결과. 직원 관리 전용 페이지는 회의 결정으로 제외하며 교대 배정 UI/API 범위는 팀에서 별도 확인 |
| 로그·지역·기준 MP16, MP18~19 | `/logs`, `/verify`, `/fac-list`, `/pm-settings` | 이벤트·전광판·통제전달·번호판 판별 로그 조회, 지역 배정, 기준값 변경 이력 |
| 예지보전·인수인계·챗봇 MP20~23 | `/pm-equipment`, `/pm-queue`, `/pm-history`, `/shift-report`, `/bot-logs`, `/bot-stats` | 설비 점수/센서/이벤트/조치, 미처리 건 이월, 챗봇 미답변 로그와 FAQ·유사어 관리 |
| 고객 계정·차량·문의·알림 CP01~03 | `/login`, `/signup`, `/my-*` | 고객 가입/로그인/비밀번호 재설정, 차량·문의·알림, 탈퇴/삭제 상태 필터 |
| 고객 지도·상세·날씨 CP05~08 | `/c-map`, `/fac-list`, `/fac-detail` | 지역·지하차도·상태·예측·날씨 조회. 예측 그래프 값과 관측값을 구분 |
| 고객 공지·FAQ·챗봇 CP09~10, CP14 | `/c-notice`, `/info/faq`, 챗봇 | 공지/FAQ 조회수, FAQ 기반 응답, 미답변 대화 기록 |
| 앱 계정·알림·챗봇 CA01~04 | `/customer-app/*` | 웹과 같은 고객/차량/문의 데이터를 사용하고 앱 기기 토큰을 별도 등록·만료 처리 |

## 회의 반영 사항

- 직원 관리 화면은 제외했습니다. `/staff`는 관리자 대시보드로 연결되며 전용 Vue/CSS/runtime은 제거했습니다.
- 상세 화면에는 이미 개요·설비·전광판·CCTV·설정 탭이 있습니다. 점검 대기/상태는 예지보전 화면에서 처리하고, 수동 판별은 `/verify`로 분리합니다.
- 통제/해제는 관리자 확인 후 수행하며, 위험 이벤트나 번호판 인식만으로 도로를 자동 제어하지 않습니다. 전달 문서는 확인 단계에서 생성합니다.
- 관리자 상세의 이벤트 로그는 시설 필터가 적용된 통합 로그 화면으로 연결합니다. 위험 추이 기준은 회의에서 6시간/8시간이 확정되지 않아 현재 예시값을 그대로 두었습니다.
- 관리자 전용 `점검 중` 상태와 고객 화면의 `통제` 표시는 서로 다른 표현으로 유지해야 합니다. 실제 상태 필드와 변환은 API 계약에서 정해야 합니다.

## 백그라운드 작업

- 기상청 관측/예보 수집 및 지역별 최신 예보 갱신
- 지하차도 위험도 예측 점수와 단계 변경 저장
- 번호판 이벤트와 등록 차량 매칭 후 알림 생성
- 예지보전 점수·이벤트 계산
- 관리자의 전화 인증 완료 후 계정 활성화
- 만료된 앱 기기 토큰 비활성화

SMS/푸시/외부기관 연동은 흐름도에서 정의한 대상과 결과 기록 규칙을 그대로 따르고, 프런트 화면에서 성공으로 가정하지 않아야 합니다. 통제 상태 변경은 관리자가 명시적으로 실행하는 흐름입니다.

## 흐름도에서 추가로 확인할 점

문서에는 데이터 엔터티와 화면별 책임은 있지만, 실제 API 주소·메서드·필드 스키마·오류 형식은 없습니다. 구현 전에 백엔드 팀으로부터 OpenAPI/요청·응답 예시, 인증 쿠키 정책, 권한 오류 규격을 받아야 합니다. SUPER_ADMIN 역할은 두지 않고 REGIONAL_ADMIN 및 담당 지역 기준으로 제한한다는 점도 권한 설계에 반영해야 합니다.
